# Analysis Lane Router — right lane before work

Universal Quality-OS gate #1: study ≠ research ≠ audit ≠ investigate ≠ evaluate ≠ learn. Picking the wrong lane wastes the whole run. Decide the lane in ONE step, then use the lane owner:

| Lane | The goal | Route to (existing owner) |
|---|---|---|
| **Study / teardown** | Master a body of content (PDF, course, codebase, creator's system) → understanding + reusable vault notes | study kits (teardown pattern), `codebase-onboarding`, vault notes |
| **Research** | Unknown external facts, cited | `research-ops` → `deep-research` / `exa-search` / `parallel-web` |
| **Audit** | Check something against a standard/policy/checklist | `security-audit`, domain audit skills, `reality-checker` |
| **Investigate** | Root-cause a bug/regression/unexpected behavior | `systematic-debugging`, `investigate` |
| **Evaluate** | Compare/score options against criteria | `agent-eval`, `statistical-analysis`, rubrics |
| **Learn** | Turn a repeated finding into durable capability | `continuous-learning-v2`, `learn`, `skill-creator` |

**Decision questions (answer in order):**
1. Is the target a body of content to MASTER (study) or an unknown fact to FIND (research)?
2. Is there a standard to check AGAINST (audit) or a broken thing to root-cause (investigate)?
3. Are we CHOOSING between options with a score (evaluate)?
4. Has this finding appeared ≥2 times already (learn — promote it)?

Mixed ask → split into lanes and run each; every lane's output follows the `analysis-contract` skill (evidence labels + output shape + rubric gate).

**House precedents:** creator teardowns (Kallaway, Motion//Prompt, Jev) = Study lane; the Motion//Prompt teardown is the shape of a good study output; fresh-facts briefs = Research lane with E1/E2/E3 labels.

Do not create a new skill for a lane that exists; do not bulk-install external skill sets for lanes (Overseer library + selective junctions only — see the plan's Phase 4 verdict table).
